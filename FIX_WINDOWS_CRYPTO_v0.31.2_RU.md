# SnowRunner Helper v0.31.2 — исправление старта установленного EXE

## Причина
В рабочем журнале GitHub Actions для v0.31.1 найдена строка
`Library not found: could not resolve 'python3t.dll', dependency of ... _rust.pyd`.
Команда `py -m venv` выбрала системный Python 3.15, хотя workflow настроил 3.11.
В упакованном EXE оказалась библиотека от несовместимого интерпретатора.

## Исправлено
1. `build_windows.bat` требует CPython **3.11 x64** и использует `python`,
   добавленный `actions/setup-python` в PATH, вместо `py`.
2. Перед каждой сборкой пересоздаётся временное окружение `.build-venv`.
3. `release_tools/verify_freeze_runtime.py` проверяет импорт _rust.pyd и
   его PE-таблицу DLL; при зависимости `python3t.dll` сборка останавливается.
4. В приложение добавлен безопасный флаг `--self-test`: он не открывает GUI,
   не изменяет профили и проверяет криптографические библиотеки и ресурсы.
5. В release.yml новый шаг запускает скомпилированный EXE до создания установщика.
6. Версия поднята до `0.31.2`; AppId и пользовательские данные не затронуты.

## Применение
Скопируйте файлы из этого ZIP в корень локального GitHub репозитория
`Документы\GitHub\SnowRunner-Helper` с заменой файлов. Не удаляйте
другие файлы и папки. В GitHub Desktop: Changes → Summary
`Fix frozen Windows crypto runtime v0.31.2` → Commit to main → Push origin.

Дождитесь зелёного `Validate SnowRunner Helper` на ветке main.
После этого в CMD из корня репозитория выполните:

    git tag v0.31.2
    git push origin v0.31.2

Проверьте GitHub Actions: `build-windows` должен пройти новую проверку
`Smoke-test frozen Windows EXE`, затем `sign-and-release` опубликует установщик.
Установите v0.31.2 поверх v0.31.1, если новый релиз успешно опубликован,
и проверьте открытие настоящего GUI на пользовательском Windows ПК.
Старая версия v0.31.1 может оставаться нерабочей, не рекомендуйте её пользователям.

**Не добавляйте приватные OTA-ключи и не перезаписывайте старые теги.**
