# SnowRunner Helper v0.31.0 — GitHub Actions (подготовлено, не опубликовано)

Репозиторий: https://github.com/FASBER/SnowRunner-Helper

Этот проект включает два файла:

- `.github/workflows/checks.yml`: тесты Python при изменениях и pull requests; без доступа к ключу подписи.
- `.github/workflows/release.yml`: при **теге `v0.31.0`** строит `SnowRunnerHelper.exe` на Windows, собирает Inno Setup, затем **в отдельном задании** подписывает `update.json` и создаёт обычный GitHub Release с EXE и манифестом.

## Шаги владельца (через сайт GitHub или Git)

1. Проверьте, что публичное распространение файлов проекта допустимо (особенно игровых изображений). **Не загружайте** файлы сохранений SnowRunner, оригинальные игровые архивы, чужие защищённые материалы или приватные ключи.
2. Добавьте исходники из данного архива **с сохранением структуры**, включая скрытую папку `.github/workflows`. ZIP нельзя просто загрузить одним файлом — содержимое должно стать файлами репозитория. Можно использовать `git add/commit/push` на компьютере или веб-редактор GitHub.
3. На доверенном Windows/Linux ПК создайте пару ключей:
   `python release_tools/generate_key.py <ПУТЬ_ВНЕ_РЕПОЗИТОРИЯ>/snowrunner_ed25519.pem`
   Требуется `pip install cryptography`. Запишите напечатанный **публичный** ключ base64.
4. GitHub → репозиторий → Settings → Secrets and variables → Actions:
   - Вкладка **Variables**: создайте `OTA_ED25519_PUBLIC_BASE64` со значением публичного ключа base64.
   - Вкладка **Secrets**: создайте `OTA_ED25519_PRIVATE_PEM` и вставьте **полное содержимое PEM** приватного ключа.
   - Риски: этот секрет становится доступен доверенному release-workflow. Любой, кто может изменить release-workflow или запустить тег с вредоносным кодом, потенциально может извлечь его. Ограничьте доступ на запись, защитите release-теги и проверяйте изменения workflows. Если не хотите хранить приватный ключ на GitHub — используйте ручную публикацию из `release_tools/prepare_github_release.py` вместо автоматической.
5. В Settings → Actions → General убедитесь, что GitHub Actions включены и что релизное задание получает разрешение `contents: write` через `permissions` в workflow (политики репозитория/организации могут ограничить его). **Не нужно выдавать ChatGPT право записи** для сборки на стороне GitHub.
6. Сначала в Actions проверьте `Validate SnowRunner Helper`. Если тесты не прошли, не выпускайте версию.
7. После проверки создайте и отправьте тег **`v0.31.0`** на ту же версию исходников (например, `git tag v0.31.0 && git push origin v0.31.0`). Публикация произойдёт только при наличии двух корректных значений ключей и успешной сборке.
8. В GitHub → **Actions** проверьте два задания `build-windows` и `sign-and-release`. Затем откройте Releases и убедитесь в наличии `SnowRunnerHelper_Setup_v0.31.0.exe` и `update.json`.
9. На настоящем Windows-компьютере проверьте выбор папки установки, запуск, обновление с более старой установленной версии и сохранность профилей. Установку **самой первой OTA-совместимой версии** пользователь должен выполнить вручную.

## Как выпускать следующие версии

Обновите `version.json`, `VERSION.txt`, `setup_snowrunner.iss`, `build_installer_windows.bat` (включая имя output), резервное значение в `update_config.py` и зависящие от версии тесты. Тег и файл `SnowRunnerHelper_Setup_vX.Y.Z.exe` должны соответствовать ровно `X.Y.Z`. Затем отправьте код и новый тег. **Не переделывайте и не перезаписывайте старые теги релизов.**

## Безопасность и ограничения

- Публичный OTA-ключ добавляется в **собираемый EXE**, а не в репозиторий; пустое значение в исходном `update_config.py` предусмотрено намеренно. При отсутствии ключа workflow завершится с ошибкой, не публикуя обновление.
- Секрет подписи доступен только отдельному job `sign-and-release` после сборки; PR не запускают этот job.
- `update.json` подписывается Ed25519, содержит SHA-256 и URL готового EXE. Ключи проверяются на соответствие.
- **Ed25519 для OTA не является цифровой подписью Authenticode Windows**. Для обхода предупреждений SmartScreen может потребоваться отдельно подписать установщик сертификатом кода (до подписания OTA-манифеста).
- Фактический Windows EXE не собирался и не тестировался в этой среде. Запуск Actions, успешная сборка Inno Setup и OTA-проверка должны быть подтверждены в GitHub/Windows.
- Не публикуйте релиз до проверки прав на распространяемые изображения.
