# OTA-обновления через GitHub Releases — инструкция владельцу

Вы можете публиковать обновления на GitHub без отдельного веб-сервера. Используйте **публичный** репозиторий для свободного скачивания обычным пользователям без GitHub-токенов.

## Первоначальная настройка (один раз)

1. Создайте GitHub-репозиторий, например `FASBER/SnowRunner-Helper`. Не добавляйте в Git файлы игровых сохранений и секретные ключи.
2. На своём доверенном ПК создайте закрытый ключ **вне проекта**:
   `python release_tools/generate_key.py D:\Secrets\snowrunner_ed25519.pem`.
   Запишите публичный ключ (строка base64), выведенный командой, в безопасное место.
3. Откройте `update_config.py`, пропишите `GITHUB_OWNER`, `GITHUB_REPO` и `PUBLIC_KEY_ED25519_BASE64`. Если один из параметров отсутствует, OTA остаётся отключённым. **Токен GitHub в приложение добавлять не нужно.**
4. Соберите начальный Windows EXE и установщик: `build_installer_windows.bat`. Убедитесь, что получился `installer_build\SnowRunnerHelper_Setup_v0.30.0.exe`. Установите именно эту OTA-совместимую сборку пользователям; в уже выпущенной v27 GitHub-адрес и ключ не были встроены, и она не сможет самостоятельно переключиться на GitHub.

## Выпуск каждой новой версии (пример 0.30.1)

1. Измените `version.json` и версию Inno Setup в `setup_snowrunner.iss` на **один и тот же номер** (например `0.30.1`). Имя выходного файла обязательно: `SnowRunnerHelper_Setup_v0.30.1.exe`.
2. Соберите и проверьте Windows Setup.exe командой `build_installer_windows.bat`. Желательно подписать **Windows Authenticode**, это отдельная подпись для доверия Windows.
3. Подготовьте подписанный JSON-манифест из **последней готовой** версии EXE (не изменяйте EXE после подписи манифеста):

   ```bat
   python release_tools\prepare_github_release.py FASBER SnowRunner-Helper 0.30.1 installer_build\SnowRunnerHelper_Setup_v0.30.1.exe D:\Secrets\snowrunner_ed25519.pem --notes "Исправления и улучшения" --output update.json
   ```

4. В браузере GitHub: **ваш репозиторий → Releases → Draft a new release**. Создайте тег `v0.30.1`, приложите два файла: `SnowRunnerHelper_Setup_v0.30.1.exe` и `update.json`. Укажите описание изменений. Опубликуйте релиз как **обычный стабильный Release**, не Draft и не Pre-release.
5. Клиенты со старой версией будут искать `https://github.com/FASBER/SnowRunner-Helper/releases/latest/download/update.json`, проверят Ed25519 подпись, новую версию, HTTPS-ссылку, размер и SHA-256, а затем предложат скачать и запустить установщик. В опубликованном релизе должен присутствовать файл EXE с именем, указанным в `update.json`.

## Условия безопасности и ограничения

- Закрытый `*.pem` нельзя загружать в GitHub и отправлять пользователям. Публичный ключ можно встраивать в EXE.
- Если кто-то заменит файл `update.json` или установщик, проверка подписи или SHA-256 отклонит обновление.
- Используйте неизменные номера тегов и файлов релизов; не перезаписывайте уже опубликованный релиз с тем же номером.
- `releases/latest` подходит только для **стабильных** релизов; для тестовых бета-версий нужен отдельный канал.
- Проверьте установку обновлений на Windows и сохранность профилей до публикации.
- В отсутствие настроенного репозитория и публичного ключа OTA безопасно отключено.
- Скрипт публикации готовит локальный `update.json`, **не загружает файлы в GitHub автоматически**. Файлы добавляются вручную через страницу Releases.
